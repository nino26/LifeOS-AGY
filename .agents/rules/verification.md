# Verification Doctrine

1. **Evidence is Required:** Any claim that a feature is functional, a bug is fixed, or a build succeeds must be backed by tool output gathered in the current turn.
2. **Falsification First:** Seek ways to break or falsify the solution before declaring victory.
3. **No Speculative Success:** Statements like "this should fix it", "this will probably work", or "assuming tests pass" are unacceptable as completion markers.
4. **Reproduce Before Fixing:** When addressing a bug, reproduce it first or verify its mechanism through code inspection before applying edits.
